# sloppy-seconds — AGENTS.md

## What this is
A static, GitHub-content-driven directory website tracking AI-assisted open-source **replacements** for commercial or closed-source software — cleanroom rebuilds, functional clones, "very similar" alternatives, and AI-assisted language ports of existing software (desktop apps, game engines, suites, chips/protocols, dev tooling). "Cleanroom" is one provenance tag among several, not the only entry criterion.

- **Data = content**: every entry is a file in this repo (YAML/markdown frontmatter + optional assets). The site renders the repo; there is no backend, no DB, no build-time scraping of third-party sites.
- **Site = Vite SPA** (Astro or Vue, see PLAN.md) hosted on GitHub Pages.
- **Freshness = GitHub Actions**: a scheduled workflow calls the GitHub API for each listed repo (stars, pushed_at, license, language, release) and commits/updates a generated `stats.json`. Site reads `stats.json`, never calls the GitHub API client-side.

## Repo layout (target)
```
apps/<slug>.md        # one file per tracked project (frontmatter = data, body = notes)
content/              # markdown pages (about, methodology, category intros)
assets/               # icons, screenshots (webp, lazy-loaded)
stats/stats.json      # GENERATED — do not edit by hand
src/                  # frontend (see PLAN.md for stack decision)
docs/                 # contributor + data-schema docs
```

## Rules for agents working in this repo
1. **Never hand-edit `stats/stats.json`** — it is generated by `.github/workflows/refresh-stats.yml`.
2. Adding a project = adding one `apps/<slug>.md` file that passes the schema in `docs/schema.md`. No other files change.
3. **Inclusion rules** (all required): (a) open source, (b) AI-assisted or AI-generated (co-author commits, README statement, or credible press — mark `ai_assisted: verified|claimed|unverified`), (c) targets a commercial/closed product, a proprietary format/protocol/chip, or is an AI-assisted language port of notable existing software. `modelled_on` is still the core field.
4. **Provenance honesty**: the `cleanroom_claim` field records only what the project itself says (from its README, with `claim_source` URL). We do not audit or opine on legality. "Clone" and "very similar" are first-class `type` values — not lesser entries.
5. **Curation decisions are recorded**: every repo considered (incl. rejects) gets a line in `docs/decisions.md` with a one-line rationale, so the dataset is reproducible and contributors can appeal.
6. **No scraping of vendor sites** (Adobe/Microsoft etc.) — data comes from the projects' own repos/READMEs.
7. Keep the site fully static: no server-side code, no client-side API calls beyond the bundled JSON. Everything must work from `gh-pages` + `raw.githubusercontent`.
8. Screenshots: prefer linking out to the project's own repo assets or use a `screenshot` field that we mirror locally only with the project's permission (their repo is open-source, license-check first).

## Committing
- **Commit on every major change** — a "major change" is any user-visible feature, fix, or data update. Don't batch unrelated changes into one commit.
- Conventional commit format: `feat:`, `fix:`, `chore:`, `docs:`, `ci:`
- Update `CHANGELOG.md` with each user-visible change (one line per entry, newest first).
- Generated files (`stats/stats.json`) get their own `chore:` commit from CI — don't mix them with manual changes.

## Changelog
Maintain `CHANGELOG.md` at the repo root. Format:
```
## [unreleased]
### Added / Changed / Fixed / Removed
- one-line description (link to commit if useful)
```
Roll `[unreleased]` into a dated section when deploying.

## Verification
- `npm run build` must succeed and produce a deployable `dist/`.
- Schema validation (see PLAN.md Phase 1) must pass for every `apps/*.md`.
- Lighthouse target: performance > 90 on the home page, zero layout shift.
