# Contributing

## Adding a project

1. Create `apps/<slug>.md` with frontmatter matching the schema in [`docs/schema.md`](schema.md).
2. The filename must equal the `slug` field.
3. That's it — one file, no other changes needed.

### Inclusion rules (all required)

- **(a)** Open source
- **(b)** AI-assisted or AI-generated (co-author commits, README statement, or credible press) — mark `ai_assisted: verified|claimed|unverified`
- **(c)** Targets a commercial/closed product, a proprietary format/protocol/chip, or is an AI-assisted language port of notable existing software

### Provenance honesty

The `cleanroom_claim` field records **only what the project itself says** (from its README, with a `claim_source` URL). We do not audit or opine on legality. "Clone" and "very similar" are first-class `type` values — not lesser entries.

### Decision log

Every repo considered (including rejects) gets a line in [`docs/decisions.md`](decisions.md) with a one-line rationale. A rejected project can be re-argued by opening an issue; if accepted, it moves to INCLUDE and an `apps/<slug>.md` file is created.

## What NOT to do

- **Never hand-edit `stats/stats.json`** — it is generated by the refresh workflow.
- **No scraping of vendor sites** — data comes from the projects' own repos/READMEs only.
- **No legal verdicts** — record claims, cite sources, stay neutral.

## Suggesting a project

Open an issue using the [suggest-project template](https://github.com/owner/sloppy-seconds/issues/new?template=suggest-project.yml) with:
- Repo URL
- Modelled-on product
- Evidence of AI assistance (link to co-author commit, README statement, or press)
- License
