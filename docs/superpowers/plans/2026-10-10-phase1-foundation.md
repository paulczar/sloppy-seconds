# Phase 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a working static directory site — buildable, deployed to GitHub Pages, seeded with the triaged dataset, with automatically refreshing live GitHub stats.

**Architecture:** The repo is the database. One `apps/<slug>.md` file per tracked project carries all curation data in Zod-validated frontmatter. Astro loads them at build time into static pages (zero client-side fetches for data). A scheduled GitHub Actions workflow hits the GitHub REST API for each entry and commits `stats/stats.json`; the commit triggers a redeploy. No backend, no database, no external service.

**Tech Stack:** Astro 5, Vue 3 (islands, Phase 2), Tailwind 4 (`@tailwindcss/vite`), Zod via `astro:content` glob loader, Vitest, Node 20, GitHub Actions + GitHub Pages.

**Spec:** `PLAN.md` (research, scope, schema §3, phases §5, triage §1d) and `AGENTS.md` (inclusion rules, repo rules, verification bar).

## Global Constraints

- Node 20+; npm as the package manager; ESM only (`"type": "module"`).
- Astro 5.x, `@astrojs/vue`, `@tailwindcss/vite`, Vitest 3.x.
- **Static output only.** No server routes, no client-side API calls. All data bundled at build time. Must work from `gh-pages` + `raw.githubusercontent`.
- **Never hand-edit `stats/stats.json`** (AGENTS.md rule 1). It is generated by `scripts/refresh-stats.mjs`.
- Adding a project changes exactly one file: `apps/<slug>.md`. No other file changes.
- Frontmatter schema is defined once in `src/lib/schema.ts` and consumed by `src/content.config.ts`. `docs/schema.md` documents it for contributors and is not a second source of truth.
- Schema fields and enum values are copied verbatim from `PLAN.md` §3, with one addition: the `category` enum gains `os` (needed by MicaNT); `PLAN.md` §3's list is extended, not replaced.
- Zero JS shipped by default (Astro default). Any island added must be justified in its task.
- Include `site` and `base` in `astro.config.mjs` so Pages URLs resolve; internal links use a helper, never string concatenation.
- Site display name is undecided (`PLAN.md` §6); use `sloppy-seconds` as the site name in config and copy until a name is chosen.

## Review Focus

Failure modes the spec implies but no single task's happy path exercises. Each line names the condition, the behavior a reasonable person expects, and the task that owns it.

1. **An entry exists but its stats are missing or stale** (new app added, cron hasn't run) — the card/page must still render, with a "stats pending" state, never a crash or an empty section. Owned by Task 6.
2. **A tracked repo is renamed, deleted, or made private upstream** — the fetch fails; the pipeline must keep the last known stats, flag them `stale: true`, and not blank the entry. Owned by Task 4.
3. **Many entries share one `modelled_on`** (9 Adobe/Office apps model Photoshop/Word/Excel; 7 `franken*` repos model libraries) — grouping and counts must aggregate rather than assume `modelled_on` is unique. Owned by Task 6.
4. **The stats run fails partway or hits the rate limit** — no partial `stats.json` may be committed (write to a temp file, then atomically rename), and the process must exit non-zero. Owned by Task 4.
5. **A repo has no license, no language, or no releases** — chips must be omitted rather than rendering `null`, `undefined`, or an empty badge. Owned by Tasks 4 and 5.
